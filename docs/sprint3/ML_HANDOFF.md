# Спринт 3. Расчётный модуль и подключение дашборда

Модуль строит график фиксированной сделки и оценивает будущие платежи по базовой кривой и выбранному сценарию команды 2. Демостенд запускает три однофакторных опыта с одной синтетической сделкой `S3-DEMO-001`.

## Запуск

Из корня репозитория. Нужен Python 3.10+ и `openpyxl` из `requirements-ml.txt`. Файл кривых передаётся отдельно.

```powershell
python -m pip install -r requirements-ml.txt
python -m ml_sprint3 demo --deal ml_sprint3/demo_deal.json --curves inputs/IRRBB_stress_curves.xlsx --valuation-date 2026-11-20 --output outputs/ml_sprint3_demo
python -m unittest discover -s tests
```

В репозитории лежат [контрольный JSON](../../outputs/ml_sprint3/results.json) и [журнал CSV](../../outputs/ml_sprint3/journal.csv). Для повтора выберите новый каталог. Расчёт спринта 3 работает без Excel. Изменённую книгу кривых следует пересчитать и сохранить в Excel перед импортом, чтобы обновить результаты формул.

Для интерактивных запросов есть `compare` с теми же входами, что у `demo`. Опции `--payment-type RGM` и `--day-count ACT/360` меняют соответствующие параметры. Для опыта со стрессом укажите `--reference-scenario base --scenario parallel_up`. Если `--reference-scenario` опущен, обе стороны оцениваются с одной и той же парой кривых.

## Входы

- Сделка задаётся в JSON. Поля `deal_id`, `source` и `currency` — строки. `principal` — начальный остаток в валюте сделки, `annual_rate` — годовая договорная ставка в долях (0.12 означает 12%), `rate_type` — `FIXED`.
- `start_date` — начало начисления. Календарь задаётся списком возрастающих дат `payment_dates` или целыми положительными `term_months` и `payment_interval_months`. Даты в формате YYYY-MM-DD. При генерации используется день месяца из `start_date` с переносом на конец короткого месяца. Дата погашения включается даже при неполном последнем периоде.
- `payment_type` принимает `ANN`, `RGM` и `SIMPLE`. Для `day_count` доступны `ACT/365` (фиксированный делитель), `ACT/360` и `ACT/ACT ISDA`. Команда `demo` ожидает исходную пару `ANN` и `ACT/365`. Команда `compare` принимает любую реализованную пару.
- Валюта кривых — RUB по указанному в книге источнику ОФЗ. Из листа `IRRBB` берутся метки и сроки `B24:T25`, база `B30:T30` и шесть сценариев из строк 36, 39, 42, 45, 48 и 51. Ставки книги делятся на 100 при импорте. Проверяются структура, сроки, единицы по заголовкам и равенство стрессовой ставки базе со сдвигом с учётом floor.
- `--valuation-date` задаёт дату оценки. Книга не указывает дату среза кривых, поэтому у демонстрационного результата `market.source.as_of` равен `null`. При подтверждении даты можно передать `--curve-date`. Модуль проверит её совпадение с датой оценки. Связь с ключевой ставкой не задана, `key_rate_shock_pp` равен `null`. В сценарии `parallel_up` +4 п.п. относятся к кривой доходности.

## Расчёт

Проценты за период равны произведению остатка на начало, договорной ставки и доли года. В ACT/365 и ACT/360 доля равна числу фактических дней, делённому на 365 или 360. В ACT/ACT ISDA дни обычных лет делятся на 365, дни високосных — на 366, затем доли складываются. В период входят день начала и все дни до даты платежа. Для ANN уровень платежа учитывает доли года всех периодов. У RGM равные доли погашения тела, у SIMPLE тело погашается в конце. Последний платёж закрывает остаток. Промежуточного округления до копеек нет. График с отрицательной амортизацией ANN не поддерживается.

Для платежа после даты оценки срок `t` равен фактическим дням от даты оценки, делённым на 365. Для каждой кривой ставка `r(t)` интерполируется линейно между сроками книги. За границами сетки берётся ближайшая ставка. Применяется непрерывное дисконтирование `DF = exp(−r(t) × t)`. Это рабочее правило для демонстрации. Договорная база начисления процентов меняет платежи, а сроки дисконтирования рассчитываются по ACT/365 во всех опытах.

`base_pv` и `stress_pv` — суммы дисконтированных будущих платежей без начальной выдачи. `dnpv = stress_pv − base_pv` внутри одного состояния. `delta_metrics.dnpv` — изменение сценарной разницы между состояниями. Показатель на экране следует назвать «PV денежных потоков».

## Контракт для AI Engineer

- `results.json`: `states[control_state]` содержит исходный график и показатели. Каждый опыт в `experiments` содержит ключи `before_state` и `after_state` для поиска в `states`, `changed_parameters`, `fixed_inputs` и `delta_metrics`. `scenario_metrics` даёт оценки контрольной сделки для базы и всех шести сценариев.
- В состоянии `deal` содержит фактические входы, `schedule` — строки с датами, начальным и конечным остатками, телом, процентами и платежом. В новых расчётах `year_fraction` содержит долю года для начисления процентов, а `day_count_terms` показывает число дней по каждому делителю. `schedule[i].discounting` содержит срок, ставки, DF и PV платежа для обеих кривых. Для платежей в дату оценки и ранее поле равно `null`. Суммы тела и процентов в `metrics` охватывают весь договорный график.
- В `market` лежат источник с SHA-256, общая сетка `tenors_years`, базовая и стрессовые кривые, сдвиги кривых в п.п. и правило дисконтирования. Для оси доходности `zero_rates` из долей нужно перевести в проценты. Сценарий `base` оценивает обе стороны по базовой кривой и возвращает `dnpv = 0`.
- Для пересчёта используйте `Deal.from_dict` из `ml_sprint3.deal`, `load_irrbb_workbook` из `ml_sprint3.curves` и `compare(deal, curves, valuation_date, scenario_id, ...)` из `ml_sprint3.analysis`. В `comparison.json` и результате `compare` состояния доступны напрямую как `before` и `after`. Для сброса заново передайте исходную сделку без переопределений, а для шага выбора стресса укажите `reference_scenario_id="base"`.

## Контрольные значения

Демонстрационная сделка — 1 000 000 ₽, 36 ежемесячных платежей, ставка 12%, оценка на 20.11.2026. Для ANN на ACT/365 и сценария `parallel_up` PV базы составляет **958 813,95 ₽**, PV стресса **906 383,03 ₽**, dNPV **−52 430,92 ₽**. Смена ANN на RGM снижает сумму процентов на **10 695,53 ₽**. Смена ACT/365 на ACT/360 повышает её на **2 866,96 ₽**. Проценты за первые 30 дней составляют **9 863,01 ₽** и **10 000,00 ₽** соответственно.

Воспроизведение предыдущего расчёта отделено от демонстрационной сделки. Старая книга на 334 платежа дала **2 056 999,50 ₽**, **1 892 477,08 ₽** и dNPV **−164 522,41 ₽**. Разность считается до округления. В старом графике сохранены делитель 365 при подписи ACT/ACT и остаток **15 420,45 ₽**. Результат зафиксирован в [контроле спринта 2](../../outputs/ml_sprint2/baseline.json). Повтор из исходной книги запускается штатной командой `python -m ml_sprint2 --source <исходная_книга.xlsx> --output <новый_каталог> --half-point` в Windows с Excel.

Для проверки с реальной сделкой нужны график и правила команды 1. Для плавающей ставки нужны индекс, надбавка, даты и правило переоценки. CSV демонстрационного генератора DE и итоговый экран AI подключаются на стороне соответствующих ролей.
