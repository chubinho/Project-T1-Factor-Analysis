# Данные для спринта 3

Единая контрольная сделка ML и AI — `S3-DEMO-001`: 1 000 000 ₽, 36 месяцев, ежемесячный ANN, фиксированные 12% годовых, ACT/365. Начало начисления и дата демонстрационной оценки — 20.11.2026. В `outputs/de_sprint3/demo_deal.json` лежит точная копия действующей сделки ML. Та же запись стоит первой в обоих CSV. Для показа ML и AI используют этот ID.

В `outputs/de_sprint3` есть `deals_fixed.csv` для штатного расчёта и дашборда и `deals_all.csv` для проверки структуры полного набора, включая плавающие ставки. Настройки учебные. Официальные распределения не предоставлены. `manifest.json` фиксирует настройки и состав выгрузки. `count` задаёт число сгенерированных сделок сверх контрольной, `seed` управляет повторяемостью. Веса выбирают срок, график, базу начисления и вид ставки. Суммы выбираются равномерно в целых рублях, ставки равномерно в долях. Для повторной выгрузки используйте ту же конфигурацию и версию Python.

| Поле | Формат и смысл |
| --- | --- |
| deal_id | Уникальный ID. Нумерация стабильна при повторе одной конфигурации. |
| source | Происхождение параметров сделки. |
| principal | Положительная сумма в рублях. |
| currency | RUB. |
| start_date | Дата начала начисления в формате YYYY-MM-DD. |
| term_months | Срок в целых месяцах. |
| payment_interval_months | Периодичность платежей в целых месяцах. Дата погашения включается даже при неполном последнем периоде. |
| payment_type | ANN — аннуитет, RGM — равное погашение тела, SIMPLE — погашение тела в конце. |
| day_count | ACT/365 или ACT/360. |
| rate_type | FIXED или FLOAT. |
| annual_rate | Годовая ставка в долях. Для FLOAT это учебная начальная ставка. |
| rate_index | Условное имя индекса для FLOAT. |
| rate_spread | Надбавка для FLOAT в долях. |
| reset_interval_months | Учебный интервал пересмотра ставки для FLOAT. |

Последние три поля есть только в полном CSV и пусты для FIXED. Для оценки FLOAT нужны фактическая серия индекса и согласованные правила переоценки. Действующий расчёт ML принимает FIXED.

Из корня репозитория:

```sh
python3 -m pip install -r requirements-ml.txt
python3 -m de_sprint3 generate --output /tmp/de-sprint3-new
python3 -m ml_sprint3 demo --deal outputs/de_sprint3/demo_deal.json --curves ~/Downloads/IRRBB_stress_curves.xlsx --valuation-date 2026-11-20 --output /tmp/ml-sprint3-new
```

Для своего набора скопируйте `de_sprint3/default_config.json`, поменяйте параметры и передайте путь через `--config`. Каталог результата должен быть новым. На ветке с дашбордом AI команда запуска такова:

```sh
python3 -m ai_sprint3 --deals outputs/de_sprint3/deals_fixed.csv --curves ~/Downloads/IRRBB_stress_curves.xlsx --valuation-date 2026-11-20
```

## Входы команд 1 и 2

Книга команды 2 `IRRBB_stress_curves.xlsx` загружена штатным загрузчиком ML. Он проверяет 19 возрастающих сроков в годах, метки, базу, шесть стрессов и равенство «база + сдвиг» с учётом floor. Валюта RUB следует из источника ОФЗ. Ставки переведены из процентов в доли. Нормализованный файл `outputs/de_sprint3/market.json` включает лист, диапазоны, имя источника и SHA-256 как идентификатор версии. Дата среза книги и изменение ключевой ставки в ней не подтверждены. Поля `as_of` и `key_rate_shock_pp` оставлены пустыми. +4 п.п. в `parallel_up` относится к кривой доходности. Дата 20.11.2026 используется как дата демонстрационной оценки. Если дата среза подтвердится, передайте `--curve-date YYYY-MM-DD`. Команда проверит совпадение с датой оценки.

```sh
python3 -m de_sprint3 curves --source ~/Downloads/IRRBB_stress_curves.xlsx --valuation-date 2026-11-20 --output /tmp/de-market-new
python3 -m ai_sprint3 --deals outputs/de_sprint3/deals_fixed.csv --market outputs/de_sprint3/market.json
```

Для графика команды 1 подготовлен формат UTF-8 CSV с обязательными полями `deal_id,currency,payment_date,principal,interest,payment`. При необходимости добавьте `prepayment` и `subsidy` отдельными компонентами поступления. Если соответствующего столбца нет, компонент равен нулю. В пределах файла должна быть одна сделка и одна валюта. Даты должны строго возрастать после начала начисления. Суммы должны быть неотрицательными с точностью до копейки. Поле `payment` равно сумме тела, процентов и отдельно указанных компонентов. Если реальные данные используют другую трактовку субсидий или досрочных платежей, сначала следует согласовать преобразование, чтобы не посчитать их дважды.

```sh
python3 -m de_sprint3 team1 --source docs/sprint3/examples/team1-example.csv --source-version training-v1 --deal-id TEAM1-SAMPLE --start-date 2026-11-20 --output /tmp/de-team1-new
```

Результат `schedule.json` содержит проверенные строки, происхождение и версию. Пример `TEAM1-SAMPLE` учебный.

### Реальная поставка команды 1 от 21.11.2026

Файл `result.txt` содержит несколько типов событий на одну дату сделки. Его можно загрузить напрямую, без ручного преобразования в CSV.

```sh
python3 -m de_sprint3 team1-events --source ~/Downloads/result.txt --source-version received-2026-11-21 --output /tmp/de-team1-result
```

- `events.csv` хранит все исходные события с датами ISO, типом, остатком, счётчиком дней и номером строки источника. Значение `repricing` сохранено отдельно без преобразования единиц.
- `payments.csv` содержит одну строку на сделку и дату денежного потока. Поле `payment` суммирует `principal + interest + prepayment + subsidy + close`. Субсидия прибавляется к потоку поверх процентов клиента и остаётся отдельным столбцом. `close` учитывается как погашение при закрытии, что подтверждается сверкой остатков. `repricing` в сумму платежей не входит.
- `validation.json` фиксирует версию, контрольную сумму источника, статистику событий и результат сверки остатков. Первая дата каждой сделки исключена из сверки переходов, поскольку исходный входящий остаток отсутствует в TXT.

Проверено 5 835 событий по 38 сделкам, получена 2 021 строка платежей. Все 2 011 переходов остатка сошлись с точностью до 0,01. На восемь дат счётчики дней различаются по типу события, поэтому счётчик сохраняется только на уровне события. Остаток в конце каждой сделки равен нулю. Исходные знаки сохранены. Все 1 790 событий `prepayment` приходятся на даты с `interest`. Суммы досрочного погашения являются заглушками и подходят для проверки интеграции.

Валюта и единицы `repricing` отсутствуют в TXT. Перед оценкой нужно сопоставить ID с параметрами сделок и подтвердить дату оценки. Синтетическая `S3-DEMO-001` остаётся отдельным контрольным примером. Модуль ML строит свой график из параметров сделки. Для сквозной оценки внешних графиков ML нужно подключить `payments.csv` как источник готовых потоков.
