# Спринт 3. Дашборд и проверка трёх опытов

Запустите `python -m ai_sprint3` из корня репозитория после установки `requirements-ml.txt`. Откройте `http://127.0.0.1:8000`. Дашборд работает локально и использует расчёт `ml_sprint3.analysis.compare` при каждом изменении. Для другого порта передайте `--port`.

## Генерация сделок в интерфейсе

Кнопка **«Сгенерировать сделки»** открывает форму. Можно задать веса сроков, типов платежей, фиксированной и плавающей ставки, а также сумму, ставку, календарь, базу начисления и параметры пересмотра. Те же настройки и начальное число (seed) воспроизводят набор. За один запуск можно создать до 500 сделок. Для длинных графиков доступное число сделок уменьшается.

Дашборд использует генератор из `de_sprint3`. Таблица показывает все созданные сделки. Фиксированные доступны для расчёта сценариев, плавающие пока представлены параметрами. Набор действует до следующей генерации или обновления страницы.

## Порядок показа

Выберите `S3-DEMO-001`. Исходные параметры этой сделки — ANN, ACT/365, 12% годовых и 36 ежемесячных платежей. Дата оценки — 20.11.2026. При открытии и сбросе выбранной сделки применяется базовая кривая.

| Опыт | Действие | Контроль по журналу ML |
| --- | --- | --- |
| Тип платежа | Выбрать RGM | Проценты за весь срок уменьшаются на 10 695,53 ₽, PV по базовой кривой растёт на 3 011,50 ₽. В графике видны тело и проценты до и после. |
| База начисления | Вернуть исходные параметры и выбрать ACT/360 | Проценты за первый период растут с 9 863,01 до 10 000,00 ₽, за весь срок — на 2 866,96 ₽. PV по базовой кривой растёт на 2 299,01 ₽. |
| Високосный год | Вернуть исходные параметры и выбрать ACT/ACT ISDA | Для перехода с 20.12.2027 на 20.01.2028 доля года меняется с `31 / 365` на `12 / 365 + 19 / 366`. Проценты за весь срок уменьшаются на 168,31 ₽. |
| Стресс | Вернуть исходные параметры и выбрать параллельный сдвиг вверх | PV базы 958 813,95 ₽, PV по стрессовой кривой 906 383,03 ₽, dNPV −52 430,92 ₽. Доходность кривой растёт на 4 п.п. |

Журнал учитывает `parallel_up` в обоих состояниях опытов с платежами. Для сверки всех столбцов этих двух строк сначала выберите этот сценарий, затем измените тип или базу начисления. Сравнение применит выбранную пару кривых к обоим графикам. Таблица «Показатели до и после» отдельно показывает dNPV каждого графика и изменение между графиками. Смена сценария при исходном графике сравнивает оценки при выбранной и базовой кривых. При смене сразу двух параметров графика карточки показывают совместный эффект.

Сумма процентов охватывает весь срок сделки. PV включает только платежи после даты оценки. Формулы и точные входы описаны в [ML_HANDOFF.md](ML_HANDOFF.md). Ссылки на журналы и реквизиты источников доступны внизу экрана. Контроль спринта 2 относится к исходной книге и своей дате оценки.

## Подключение данных команды

По умолчанию используется [`ml_sprint3/demo_deal.json`](../../ml_sprint3/demo_deal.json) и сетка ставок из [`outputs/ml_sprint3/results.json`](../../outputs/ml_sprint3/results.json). Сохранённая сетка воспроизводит книгу команды 2, указанную в источниках. В ней не подтверждены дата среза и связь стрессов с изменением ключевой ставки.

```powershell
python -m ai_sprint3 --deals path/to/deals.csv --curves path/to/IRRBB_stress_curves.xlsx --valuation-date 2026-11-20
```

- `--deals` принимает JSON с одной записью или массивом записей и CSV в UTF-8 с заголовком. Поля CSV совпадают с контрактом ML. Для календаря используйте `term_months` и `payment_interval_months` либо `payment_dates` как JSON-массив дат в ячейке. Идентификаторы должны быть уникальными, ставки передаются в долях, поддерживаются `FIXED` и валюта загруженных кривых. Все сделки из файла появляются в списке. Смена сделки и сброс восстанавливают её собственные исходные параметры.
- `--curves` принимает книгу команды 2 через существующий загрузчик ML. Если у команды есть подтверждённая дата среза, передайте `--curve-date`. Она должна совпадать с датой оценки.
- `--market` принимает нормализованный JSON результата ML с `schema_version` и `market` вместо XLSX. Сценарий из списка IRRBB, которого нет в `market.stress_curves`, помечается как недоступный. При выборе выводится список данных, которые нужны для расчёта. Для сценария с подтверждённой величиной `key_rate_shock_pp` экран показывает её отдельно от сдвига кривой. `source_url` в записи сценария добавляет ссылку на его описание в блоке источников.

По умолчанию используется синтетическая сделка ML. Чтобы открыть все фиксированные сделки из готовой выгрузки DE, запустите `python -m ai_sprint3 --deals outputs/de_sprint3/deals_fixed.csv`.

## Готовые платежи команды 1

Положите полученный TXT в `inputs/result.txt` и выполните из корня репозитория:

```sh
python -m de_sprint3 team1-events --source inputs/result.txt --source-version received-2026-11-21 --output outputs/team1_run
python -m ai_sprint3 --deals outputs/de_sprint3/deals_fixed.csv --team1-payments outputs/team1_run/payments.csv --team1-currency RUB --valuation-date 2026-11-20 --team1-demo
```

Для готового графика обязательны валюта и дата оценки. В примере RUB и 20.11.2026 используются как учебные допущения. Флаг `--team1-demo` отмечает их на экране. Если валюта и дата подтверждены, укажите их значения и уберите этот флаг. Валюта должна совпадать с валютой кривых.

Выберите сделку из группы «Команда 1 · готовые графики» и стресс. Показываются PV базы, PV сценария, dNPV и разбивка будущих платежей. Платежи в дату оценки и ранее исключаются из PV. Сценарий меняет кривую дисконтирования, а суммы берутся из полученного графика с исходными знаками. Для сверки с командой 1 нужна её контрольная оценка на ту же дату и с теми же кривыми.
